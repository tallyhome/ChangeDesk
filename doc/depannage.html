Problèmes fréquents

Dépannage

La plupart des échecs viennent du Document Root, des droits d’écriture, de PHP trop ancien, ou d’identifiants MySQL.

Page blanche ou 500

  • Ouvrez storage/logs/laravel.log.
  • Vérifiez PHP ≥ 8.2 pour ce domaine.
  • storage/ et bootstrap/cache doivent être inscriptibles.
  • Si vendor/ manque : composer install --no-dev.

/install introuvable (404) trop tôt

  • Le fichier storage/app/installed existe déjà → l’installeur se masque. Supprimez-le seulement pour réinstaller une instance neuve.
  • Le Document Root n’atteint pas Laravel (mauvais dossier, archive extraite dans un sous-dossier).
  • mod_rewrite inactif, ou .htaccess racine absent (méthode B).

Toujours redirigé vers /install

Le middleware considère que l’app n’est pas installée s’il n’y a ni storage/app/installed ni .env avec APP_KEY. Relancez l’assistant jusqu’au bout, ou créez ces fichiers après une install CLI.

Connexion MySQL impossible

  • Préfixe cPanel oublié (user_nom).
  • Utilisateur non lié à la base, ou privilèges incomplets.
  • Host : tester localhost puis 127.0.0.1.

Installation interrompue pendant migrate

Le message d’erreur s’affiche sous le formulaire. Causes typiques : timeout PHP, mémoire, ou tables déjà partiellement créées. Augmentez max_execution_time, corrigez, réessayez. En dernier recours, videz la base et relancez.

CSS / images cassés

Document Root pas sur public/, ou URL dans APP_URL incorrecte (http vs https, mauvais hôte). Relancez php artisan storage:link si les uploads 404.

Sous-domaine client inaccessible

  1. Le DNS * résout-il ?
  2. Le vhost wildcard pointe-t-il vers le même public/ ?
  3. Le certificat couvre-t-il *.domaine ?

Si ces trois points échouent, la requête n’arrive jamais à PHP.

Le projet pèse plusieurs Go

Le code + vendor/ fait plutôt 50–150 Mo. Cherchez archives, node_modules, .git ou backups :

du -sh * .[^.]* 2>/dev/null | sort -hr | head -20

Réinstaller proprement

  1. Sauvegarder la base si elle contient des données.
  2. Supprimer storage/app/installed.
  3. Optionnel : supprimer ou vider le .env.
  4. Vider les tables (ou recréer la base).
  5. Ouvrir à nouveau /install.
Santé de l’application Laravel expose /up (health check). Cette URL n’est pas redirigée vers l’installeur.
