cPanel · WHM

Installer Evolora sur cPanel

Méthode la plus courante. L’objectif : fichiers en place, PHP 8.2, base MySQL, Document Root sur public/, puis l’assistant /install.

Créer le domaine ou sous-domaine

cPanel → Domaines. Exemple : changelog.monsite.fr. Notez le chemin du dossier (souvent /home/USER/changelog.monsite.fr).

Pointer le Document Root vers public/

Domaines → Gérer → Document Root : /home/USER/changelog.monsite.fr/public. C’est la méthode A, recommandée.

Uploader le projet

Gestionnaire de fichiers ou FTP/SFTP. Extraire l’archive dans le dossier du domaine, de façon à avoir app/, public/, vendor/ au même niveau. Si vendor/ est absent, ouvrez le Terminal cPanel et lancez Composer (voir plus bas).

PHP 8.2

cPanel → Select PHP Version / MultiPHP. Choisissez 8.2 ou 8.3 pour ce domaine. Cochez pdo_mysql, mbstring, openssl, tokenizer, xml, ctype, json, bcmath, fileinfo, curl.

Créer la base MySQL

cPanel → Bases de données MySQL : créer la base, un utilisateur, lui donner TOUS LES PRIVILÈGES. Notez nom complet (souvent préfixé user_), user et mot de passe. Détail : page base de données.

Permissions

Dans le gestionnaire de fichiers, droits 755 ou 775 sur storage et bootstrap/cache (récursif). Le .env n’existe pas encore : l’installeur le créera.

SSL

cPanel → SSL/TLS Status → AutoSSL, ou Let’s Encrypt. Attendez que https://changelog.monsite.fr soit vert.

Lancer l’assistant

Ouvrez https://changelog.monsite.fr/install (ou simplement le domaine : redirection automatique). Suivez prérequis → base + superadmin.

Méthode B — Document Root bloqué sur la racine

Si cPanel impose le dossier du domaine sans /public, gardez le .htaccess à la racine (fichier avec le point). Un fichier nommé htaccess sans point est ignoré par Apache.

cd /home/USER/changelog.monsite.fr
# Si seul « htaccess » est présent :
cp htaccess .htaccess

Ce fichier réécrit /install et tout le reste vers public/, et désactive le listing des dossiers.

Composer dans le Terminal cPanel

cd /home/USER/changelog.monsite.fr
composer install --no-dev --prefer-dist --optimize-autoloader

Sous Windows en local (PowerShell), ne pas utiliser rm -rf :

Remove-Item -Recurse -Force vendor
composer install --no-dev --prefer-dist --optimize-autoloader
Sous-domaines clients inaccessibles ? Le site central peut marcher alors que client.changelog.monsite.fr échoue. C’est DNS / vhost / SSL, pas Laravel. Voir sous-domaines wildcard.
