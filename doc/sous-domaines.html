Multi-tenant

Sous-domaines clients (wildcard)

Chaque projet client peut vivre sur slug.votredomaine.fr. Laravel est déjà prêt. Il faut que le DNS, le vhost et le SSL envoient tous ces hôtes vers le même public/.

teste.changelog.monsite.fr→ DNS *→ Apache / Nginx→ …/public→ Laravel

1. DNS wildcard

Chez le registrar, Cloudflare ou la zone DNS cPanel :

  • Type A (ou CNAME) : hôte * → même IP (ou même cible) que le domaine central.
  • Résultat : nimportequoi.changelog.monsite.fr résout comme le site principal.
ping teste.changelog.monsite.fr
nslookup teste.changelog.monsite.fr

2. Sous-domaine wildcard dans le panneau

cPanel

Domaines / Subdomains → créer :

  • Subdomain : *
  • Domain : changelog.monsite.fr
  • Document Root : le même que Laravel (…/public)

Équivalent Apache : ServerAlias *.changelog.monsite.fr.

Webuzo / Plesk / Nginx

Ajoutez un wildcard subdomain ou un server_name *.changelog.monsite.fr avec le même root. Un tutoriel cPanel / WHM / PowerDNS / AutoSSL plus détaillé se trouve dans docs/tutoriel-wildcard-cpanel-whm.md.

3. Certificat SSL wildcard

Il faut un certificat pour *.changelog.monsite.fr et le domaine apex. AutoSSL cPanel, Let’s Encrypt DNS-01, ou Caddy. Sans SSL valide, le navigateur affiche une erreur d’accès même si PHP est correct.

4. Variables Laravel

APP_URL=https://changelog.monsite.fr
CENTRAL_DOMAIN=changelog.monsite.fr
CENTRAL_DOMAINS=changelog.monsite.fr,www.changelog.monsite.fr
TENANCY_CNAME_TARGET=cname.changelog.monsite.fr

Domaines personnalisés (CNAME)

Le client pointe changelog.sonentreprise.fr en CNAME vers cname.changelog.monsite.fr, puis vérifie le DNS dans Admin → Domaine. Côté reverse-proxy avancé, l’API GET /api/ssl/ask?domain=… indique si un certificat on-demand peut être émis.

Le wizard n’configure pas le DNS L’assistant installe l’application et le premier tenant. Les enregistrements *, le vhost wildcard et le certificat se font dans le panneau d’hébergement.
