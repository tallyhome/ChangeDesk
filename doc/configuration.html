Après l’assistant

Configurer l’application

L’installeur écrit un .env de production. Vous pouvez l’ajuster (e-mail, Stripe, PayPal, domaines) puis vider le cache de config.

Variables essentielles

APP_NAME=Evolora
APP_ENV=production
APP_DEBUG=false
APP_URL=https://changelog.monsite.fr

CENTRAL_DOMAIN=changelog.monsite.fr
CENTRAL_DOMAINS=changelog.monsite.fr,www.changelog.monsite.fr
TENANCY_CNAME_TARGET=cname.changelog.monsite.fr
  • APP_URL : sans slash final.
  • CENTRAL_DOMAIN : hôte du site vitrine / login, sans https://.
  • CENTRAL_DOMAINS : liste des hôtes considérés comme « centraux » (pas un tenant).
  • TENANCY_CNAME_TARGET : cible DNS que vos clients doivent pointer pour un domaine personnalisé.

Base, session, cache

Écrits par l’installeur :

DB_CONNECTION=mysql
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=...
DB_USERNAME=...
DB_PASSWORD="..."

SESSION_DRIVER=database
QUEUE_CONNECTION=database
CACHE_STORE=database
SESSION_DOMAIN=null

Pour partager la session entre le domaine central et les sous-domaines tenants, vous pourrez passer SESSION_DOMAIN=.changelog.monsite.fr (point devant). Laissez null au début si tout passe par le domaine central.

E-mail

Par défaut MAIL_MAILER=log (les mails vont dans les logs). En production, configurez SMTP (cPanel, Mailgun, SES, etc.) :

MAIL_MAILER=smtp
MAIL_HOST=mail.monsite.fr
MAIL_PORT=587
MAIL_USERNAME=noreply@monsite.fr
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS=noreply@changelog.monsite.fr
MAIL_FROM_NAME=Evolora

Facturation (optionnel)

STRIPE_KEY=
STRIPE_SECRET=
STRIPE_WEBHOOK_SECRET=
STRIPE_PRICE_PRO=
STRIPE_PRICE_BUSINESS=

PAYPAL_MODE=sandbox
PAYPAL_CLIENT_ID=
PAYPAL_CLIENT_SECRET=
PAYPAL_WEBHOOK_ID=
PAYPAL_PLAN_PRO=
PAYPAL_PLAN_BUSINESS=
BILLING_CURRENCY=eur

Webhooks à déclarer chez Stripe / PayPal :

https://changelog.monsite.fr/webhooks/stripe
https://changelog.monsite.fr/webhooks/paypal

Ces URLs sont exclues de la protection CSRF.

Après chaque modification du .env

php artisan config:clear
php artisan config:cache

Sans SSH : dans le gestionnaire de fichiers, vous pouvez supprimer bootstrap/cache/config.php pour forcer Laravel à relire le .env (remettez un cache ensuite si possible).

Sécurité post-install

  • APP_DEBUG=false en production
  • Vérifier que storage/app/installed existe (le wizard se désactive tout seul)
  • Document Root = public/
  • Ne pas commiter le .env
Mises à jour GitHub Le jeton d’accès pour les mises à jour n’est pas dans le .env : il se configure dans app/Support/GithubUpdateAuth.php (dépôt privé : PAT lecture Contents).
